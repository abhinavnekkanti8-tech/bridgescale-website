# BridgeScale Service Model Documentation Pack

This folder defines the proposed BridgeScale service model after reviewing competitor references, especially the Knex tri-party agreement, SOW, and contracts/payments FAQ model.

The goal is to align BridgeScale around one clear commercial operating system:

- a standard tri-party agreement
- engagement-specific editable SOWs
- a simplified service menu
- role/category education
- consistent contracting, payments, compliance, invoice, tax-document, and party-obligation language

## Working Decisions

These are proposed decisions for evaluation, not final legal policy.

- BridgeScale should adopt a Knex-style tri-party agreement model.
- BridgeScale should use one standard platform agreement plus one editable SOW per engagement.
- BridgeScale should launch with the full engagement menu, not defer advanced models.
- BridgeScale should explain fractional work through outcomes and services first, then map roles underneath those services.
- BridgeScale should create a dedicated Contracts & Payments FAQ similar in purpose to Knex's FAQ, rewritten for BridgeScale's diaspora GTM model.

## Open Decisions

These need founder/legal/finance confirmation before implementation:

- Exact company unlock fee and currency.
- Exact platform fee structure and who pays it.
- Whether BridgeScale charges a full-time conversion fee, and how it is calculated.
- Whether BridgeScale will issue US 1099s directly, through a payment partner, or not at launch.
- Whether BridgeScale will support true escrow, milestone gating, or simpler invoice/payment workflows at launch.
- Whether equity/hybrid engagements use FAST, a BridgeScale addendum, or partner counsel-generated documents.
