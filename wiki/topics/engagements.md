# Engagements

*Sources: `backend/src/engagements/` · `backend/src/closeout/` · `backend/prisma/schema.prisma`*

---

## Purpose
[coverage: high]

The active workspace where a startup and operator execute the agreed scope. Initialized from a `FULLY_SIGNED` contract. Tracks milestones, notes, activity, health score, nudges, escalations, and closeout.

---

## Architecture
[coverage: high]

```
EngagementsController / EngagementsService
  └── PrismaService   (milestones, notes, logs, health snapshots, nudges, escalations)

CloseoutController / CloseoutService
  └── PrismaService + AiService   (AI-generated closeout report)
```

## Data
[coverage: high]

**Engagement status flow:** `NOT_STARTED → ACTIVE → PAUSED → COMPLETED | TERMINATED`

**`Engagement` key fields:**
- `contractId` (unique) — one engagement per contract
- `startupId` / `operatorId` — denormalized from contract's SOW for query efficiency
- `healthScore: Int` — 0–100, decremented by overdue milestones, payment issues, inactivity
- `startDate`, `endDate`

**`EngagementMilestone` status:** `PENDING → IN_PROGRESS → REVIEW → COMPLETED`

**`WorkspaceNote`:** Pinnable notes with `isPinned` flag. Includes `authorId` + author name/email for display.

**`HealthScoreSnapshot`:** Periodic snapshots. `components` JSON typically:
```json
{ "milestonePace": 20, "communicationFreq": 25, "paymentStatus": 30, "milestoneQuality": 25 }
```

**`SystemNudge` types:** `MILESTONE_DUE_SOON`, `MILESTONE_OVERDUE`, `INACTIVITY_WARNING`, `PAYMENT_REMINDER`, `MEETING_PREP`

**`CloseoutReport` fields:**
- `summary`, `outcomes`, `nextSteps` (text)
- `generatedByAi: Boolean`
- `status: DRAFT | PUBLISHED`

## Key Decisions
[coverage: medium]

**Engagement is created from contract:** `initializeEngagement` checks `contract.status === 'FULLY_SIGNED'` — no manual initialization without a signed contract. It also warns (but doesn't fail) if no invoice is paid yet.

**Activity log for audit:** Every significant action (milestone completion, note added, status change) is logged to `ActivityLog`. The workspace endpoint returns the most recent 20 logs.

**Escalation cases independent:** `EscalationCase` is created by any user and tracked separately from health score. An open escalation doesn't automatically change engagement status — admins must act.

## Gotchas
[coverage: medium]

- `initializeEngagement` sets `status = 'ACTIVE'` immediately — there's no `NOT_STARTED` phase in practice. The enum value exists but the service skips it.
- `WorkspaceNote` has `isPinned` but no endpoint to toggle pins currently — frontend would need to add this.
- `CloseoutReport` is 1:1 with `Engagement` — you can only have one closeout per engagement. Re-generating overwrites via upsert.
- Health score is stored as a snapshot per computation — the current score on `Engagement.healthScore` is the latest value, but history is in `HealthScoreSnapshot`.
